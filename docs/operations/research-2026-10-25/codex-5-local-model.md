## Резюме

- **[интерпретация] Доказательств, оправдывающих немедленную замену Qwen3-4B-Instruct-2507 и полный перемер результатов, не найдено.**

### Архитектура и память

- **Qwen3.5:** в модели чередуются блоки DeltaNet и обычного attention. **[интерпретация]** Это сокращает растущую с контекстом часть attention/KV, но на вашем коротком относительно паспортного окна промпте ускорение зависит от CPU-ядер реализации, а не только от архитектурного названия. [Карточка Qwen3.5](https://huggingface.co/Qwen/Qwen3.5-4B/raw/main/README.md).
- **LFM2.5:** большинство блоков — short convolution, остальные — GQA. **[интерпретация]** Потенциально привлекательна для CPU, но без подходящих pp/tg нельзя вычислить время ответа. [Карточка Liquid](https://huggingface.co/LiquidAI/LFM2.5-2.6B/raw/main/README.md).
- **Gemma E2B:** per-layer embeddings уменьшают вычислительную работу относительно полного числа параметров, но сами таблицы требуют хранения. **[интерпретация]** Поэтому effective-размер нельзя подставлять вместо полного размера при расчёте RAM. [Карточка Google](https://ai.google.dev/gemma/docs/core/model_card_4).
- **MoE:** малая активная доля не отменяет хранения всех экспертов. **[интерпретация]** Для этой машины ограничение памяти важнее рекламного active-размера.

В тесте A указаны **3,7 GiB RAM / 620 KiB swap** для Qwen3.5-4B и **3,1 GiB / 346 MiB** для Gemma E2B QAT. Показатель RAM не определён строго как RSS; retrieval-модели рядом не запускались. [Тот же CPU-отчёт, дата замеров не указана](https://raw.githubusercontent.com/atiqa-ai/llamacpp-cpu-inference-evaluation/main/README.md).

**[интерпретация]** В пилоте следует задавать контекст под реальный запрос, отключать reasoning там, где он предусмотрен, и проверять отсутствие скрытой дополнительной генерации. Паспортное длинное окно для вашей задачи не требуется.

### Что именно улучшает Trust-Align

Источник — статья **v3 от 04.03.2025**, приложение I, таблица 19: **ASQA, 948 вопросов, top-5 документов**, сравнение base+ICL → Trust-Align DPO. ### Очерёдность проверки

**[интерпретация] Это рейтинг полезности пилота, а не доказанное ранжирование качества.** Численного ожидаемого выигрыша новых моделей относительно baseline ни для RU, ни для EN имеющиеся источники не устанавливают.

Размеры файлов — из §1; внешняя память и условное время — из §3. Ниже они не превращаются в прогноз RSS вашего процесса.

Baseline остаётся контрольной точкой: **около 3,3 GB процесса**, наблюдаемая медиана полного ответа **250–300 с** при разной длине ответа — данные вашего брифа, не нормированный тест.

**[интерпретация] Ни один кандидат сейчас нельзя обоснованно назвать достаточно вероятным победителем по grounded-качеству, чтобы сразу перемерять все опубликованные результаты.** Основания есть для пилота: у Qwen3.5 — проверить качество при сопоставимом размере, у Gemma — проверить сочетание качества и скорости. Trust-Align Phi стоит держать отдельной английской веткой. Phi-4-mini и Ministral не имеют достаточных положительных свидетельств для первой очереди.

### Дешёвый пилот на сохранённых вопросах

Все количества и пороги далее — **[интерпретация: предлагаемый дизайн]**, а не опубликованные результаты.

**Сначала проверить исполнимость.** Для baseline и двух первых кандидатов использовать несколько типичных сохранённых RU/EN-запросов. Проверить загрузку точного GGUF, нативный chat template, отключение reasoning, вывод `[N]`, prefill/decode, пиковую память и **прирост swap при резидентных BGE-M3 и reranker**. Для Gemma явно зафиксировать выбор Q4_K_M либо QAT Q4_0: это разные экспериментальные варианты.

Отдельный timing probe приблизить к **2300 входным и 250 выходным токенам**. В качественной части не заставлять короткий отказ дописывать ответ до заданной длины. Одинаковый текст у разных токенизаторов имеет разную длину — сохранить реальные counts.

**Основная выборка: по 20 вопросов на каждую из четырёх баз, всего 80 на модель.** Предлагаемый состав каждой базы:

| Группа | Вопросов |
|---|---:|
| Обычные вопросы, выбранные случайно | 8 |
| Прежние ответы с неподтверждённым утверждением | 4 |
| Прежние отказы, хотя ответ есть в контексте | 4 |
| Вопросы, на которые сохранённый контекст действительно не отвечает | 4 |

Если группы не набираются, добрать случайными и сохранить реальные размеры. Это диагностически обогащённая выборка; её итоговую долю good нельзя выдавать за новую оценку всего датасета.

**Зафиксировать сравнение:**

- Одни и те же сохранённые chunks, их порядок и номера; retrieval заново не запускать.
- Одинаковое содержание инструкции и политика decoding; использовать корректный нативный шаблон каждой модели.
- Baseline можно переиспользовать только при совпадении checkpoint, quant, промпта и контекстов; иначе получить свежие ответы.
- Тот же LLM judge, его версия и rubric; скрыть название генератора и случайно перемешать ответы.
- Кроме вашего `good`, сохранить отдельные вердикты по неподтверждённым утверждениям, смысловой корректности цитат, правильному отказу и лишнему отказу. Пересудить только спорные пары, от которых зависит решение.

**Предлагаемый допуск к полному перемеру:** не менее **8 чистых дополнительных good из 80** — исправленные ответы минус вновь испорченные; без ухудшения русского результата, роста лишних отказов и ухудшения памяти/времени. Это операционный порог владельца, **не доказательство статистической значимости**. Если улучшение есть только в английском, оно не обосновывает общую двуязычную замену.

**Время пилота.** По вашему диапазону медиан можно построить лишь плановый сценарий:

| Сценарий | Расчёт |
|---|---:|
| Один вариант, если среднее время окажется **250–300 с** | `80 × 250–300 с` = **5,6–6,7 ч** |
| Baseline и два кандидата, если все окажутся такими же по времени | **16,7–20 ч** |
| После короткого timing gate | Для каждого кандидата: **80 × измеренное среднее время** |

Это расчёт из данных брифа, не измеренный бюджет: сохранённые контексты могут убрать часть прежних задержек, а swap — добавить их. Загрузка моделей, скачивание и работа judge сюда не включены; их время **не найдено** без сведений о вашем исполнении. Проверять модели следует последовательно.

**[интерпретация]** Следующий кандидат нужен только если первые не проходят отбор: сначала LFM, затем меньший Qwen или английская ветка Trust-Align. Успех генератора на этом пилоте сам по себе не подтверждает надёжность передачи сложных ответов человеку: для неё должны сохраняться ваши отдельные основания отказа и эскалации.
