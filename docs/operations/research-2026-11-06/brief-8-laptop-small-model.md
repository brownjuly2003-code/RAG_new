# Рисерч 8: малая эффективная модель на ноутбуке владелицы (2026-11-06)

## Зачем

RAG-ассистент поддержки (`D:/RAG_new`) сейчас работает на Windows-ноутбуке владелицы под профилем
`codex-only`: все вызовы языковой модели идут в GPT-6-Astra через Codex (подписка ChatGPT, общий
недельный лимит со всеми её проектами). Эмбеддинги BGE-M3 и ONNX-реранкер (bge-reranker) работают
локально на CPU. Владелица хочет сохранить линию локальной модели: найти маленькую, более
эффективную модель и, вероятно позже, запускать её на этом же ноутбуке. Нужен обзор на ноябрь 2026:
какие модели и какие рантаймы реально подходят этому железу и каким ролям.

## Железо и жёсткое ограничение

- Intel Core Ultra 5 125H (Meteor Lake): 14 ядер (4P + 8E + 2LP-E), 18 потоков; прошивка ограничивает E-ядра.
- Встроенная графика Intel Arc (Xe-LPG), драйвер 32.0.101.8735; NPU Intel AI Boost.
- ОЗУ 15,5 ГБ, общая с графикой; при обычной работе владелицы свободно около 6 ГБ.
- Windows 11 Home; Python 3.11.
- Ноутбук — её рабочая машина. 03.11 Qwen3-4B-Instruct-2507 q4_K_M в Ollama на CPU (в роли помощника
  при ответе Codex) занимал минуты на вызов, один вопрос шёл 1 090 с, машина встала. Повтор
  недопустим: модель не должна забирать CPU и память так, что владелица не может работать.

## Роли модели в конвейере (на один вопрос)

1. Переформулировка запроса для поиска (короткий выход).
2. Пакетная оценка релевантности найденных фрагментов: один вызов на 5–20 фрагментов, короткий выход.
3. Ответ по отправленному контексту со ссылками `[N]` или отказ, если ответа в контексте нет;
   язык ответа равен языку вопроса.

## Вопросы

1. **Рантаймы на этом железе (Windows 11, ноябрь 2026).** OpenVINO GenAI (NPU, GPU), ONNX Runtime
   GenAI (DirectML, OpenVINO EP), Windows ML / Foundry Local, llama.cpp (Vulkan, SYCL),
   IPEX-LLM / Ollama для Intel, LM Studio и другие. Для каждого: зрелость; Python API или
   OpenAI-совместимый сервер; какие модели идут на NPU и на iGPU; квантование (INT4); ограничения
   NPU (статическая длина промпта, максимум контекста); время до первого токена и токены/с для
   моделей 1–4B на Meteor Lake (125H/155H) — измеренные числа с источником и датой; нагрузка на CPU
   и память при работе на NPU/iGPU; можно ли ограничить потоки и память.
2. **Малые модели** (до ~4B эффективных параметров или MoE с малой активной частью), ноябрь 2026,
   сильные в ответах по контексту (цитаты, отказ при отсутствии ответа), с русским и английским:
   малые Qwen3.5, Gemma 4 (E2B/E4B), Phi mini, малые Llama, SmolLM, IBM Granite (micro/tiny),
   MiniCPM, Ministral и другие свежие. Для каждой: готовые сборки OpenVINO IR INT4 (NPU/GPU) или
   ONNX; лицензия; доказательства верности контексту (Vectara hallucination leaderboard, FaithEval,
   RAGTruth и т. п.), доля ответов и отказов; русский; длина контекста.
3. **Роли 1–2 отдельно.** Какие малые модели годятся для переформулировки и оценки релевантности;
   есть ли негенеративные замены (например, порог по баллу кросс-энкодера-реранкера, который у нас
   уже есть) и что о них известно.
4. **Рекомендация:** 2–3 связки «модель + рантайм + устройство» для первой короткой проверки на
   ноутбуке — сначала для ролей 1–2, затем, если есть шанс, для роли 3; ожидаемые скорость и
   память; риски; самая безопасная процедура короткого теста (как ограничить нагрузку, как
   остановить).
