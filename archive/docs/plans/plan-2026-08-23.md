## 0. Правило приёмки слайса (заменяет текущее, действует с фазы 0)

Слайс принимается, только если выполняется хотя бы одно:

- **(а)** изменилось наблюдаемое поведение `/api/ask` или UI, и это доказывает E2E-тест;
- **(б)** выросло число реальных размеченных кейсов;
- **(в)** изменилось опубликованное число качества с провенансом (corpus SHA + code SHA + config).

«Locally complete» без (а)/(б)/(в) — не слайс, а подготовка. Это правило закрывает механизм FIN-01/FIN-02 (автопилот выбирает локально доказуемое) и обязательно для любого агентного режима работы по этому репозиторию.

## Фаза C — Рычаг качества (недели 3–4)

Закрывает FIN-10 — правило (в). Тяжёлые прогоны — **не на Windows**: iMac (`ssh julia@192.168.1.133`, 8 GB — Qwen3-8B Q4_K_M впритык) или Colab (см. Q3).

- **C.1 Бенчмарк генераторов** на 100 кейсах по существующему harness: `qwen2.5:7b` (baseline) vs `qwen3:8b` Q4_K_M vs одна модель Qwen3.5-класса. Метрики: faithfulness (LLM-judge **и** независимый NLI-чекер HHEM-2.1/MiniCheck), context precision, latency, RAM. 3 прогона на кандидата, CI разброса.
- **C.2 Второй судья:** дешёвый NLI-чекер как постоянный второй judge в eval-контуре (не LLM-судья самого себя) — остаётся в проекте независимо от исхода бенчмарка.
- **C.3 Claim-level compilation** (бриф §6.4): ответ = список material claims → каждому evidence ID → unsupported удаляется → сборка текста. Поднимает faithfulness и делает evidence bundle из фазы A содержательным.
- **C.4 Решение по модели:** менять default только при улучшении faithfulness/precision без нарушения RAM/latency; иначе — задокументированный NO-SHIP (это тоже результат).

## Условный трек — только при появлении design partner

Не начинать без внешнего триггера. Это sol §11 (этапы 1–2, 5–7) целиком:

- durable HTTP-семантика: `Idempotency-Key`, `ETag`/`If-Match`, 428/412/409/503; 1 000 contended attempts / 100 sessions / 2 replicas;
- SSE как projection persisted events, удаление direct-stream пути (FIN-04 полностью);
- service accounts, forced RLS на legacy `sessions`/`messages`, JWT `iss/aud/iat/jti` + rotation/revocation (FIN-12 полностью);
- Helm production: encrypted backup fail-closed, restore drill, NetworkPolicy, PDB, digest-pin, SBOM/SLSA (FIN-15);
- Trust Foundation шаги 5–10;
- governed action canary с business-KPI (verified resolution, recontact, handle time) и заранее объявленной статистикой.
