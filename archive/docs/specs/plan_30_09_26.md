# План повышения качества RAG_new — 30.09.2026

**Цель:** повысить смысловую точность поиска, сохранив необходимые факты и приемлемое время ответа; доказать пользу графа для вопросов, требующих нескольких источников. Основание: [аудит](../audits/audit_asta_30_09_26.md). Это план следующих работ, реализация не выполнена.

Baseline: H с production expansion — лексические precision **0.5768**, recall **0.9800**, FULL **97/100**. Для сложного Hm — **0.3263 / 0.7333**, FULL **7/15**. Эти значения из P1b нельзя смешивать с GR3 без expansion. P2 дал `RULER_DOES_NOT_TRACK`; граф в GR3 — `NO_SHIP_TO_DEFAULT`. Существующий порог 0.63 не переносить на новую шкалу.

## Условия принятия результата

- **Релевантность:** human precision@5 и precision реально отправленного контекста считаются отдельно, с явным знаменателем; nDCG@5 показывает качество порядка. Нижняя граница CI95 парного прироста precision выше нуля. Минимально полезный эффект регистрируется до holdout.
- **Полнота:** покрыты обязательные атомарные факты и все звенья multi-hop; нет новых потерь критических фактов в регрессионных кейсах. Для общей полноты/faithfulness заранее задаются non-inferiority margins и проверяются интервалы. Отсутствие статистической значимости не означает отсутствия вреда.
- **Достоверность:** ответ подтверждён цитируемыми источниками; неполный контекст вызывает уточнение/обозначение недостаточности. Доля отказов измеряется. Невалидный judge — `not_evidence`, а не пропущенный неудобный результат.
- **Задержка:** сравнение при одинаковых общих candidate/token budgets; действующий graph gate delta retrieval p95 ≤200 ms сохраняется до отдельного решения. Дополнительно заранее задаётся абсолютный SLO API на целевом оборудовании.
- **Воспроизводимость:** locked holdout не используется для выбора настроек; paired bootstrap учитывает семейства источников. Публикуются corpus/code/config SHA, версии моделей/графа, контексты, raw replies и стоимость. Старый gate 0.63 остаётся обязательным в своей шкале, пока явно не заменён.
- **Проверка реализации:** для каждого изменения поведения сначала красный регрессионный тест, затем исправление и scoped green; в конце полный релевантный прогон, Docker и модельные измерения на Mac/целевом стенде. Actions — только после восстановления доступности. UI/API acceptance не заменяется unit-тестами.

Первый результат работ — подтверждённая схема оценки и сопоставимый baseline. Следующий — один проверенный механизм улучшения с сохранённой полнотой. Новые графовые framework, смена БД и масштабное переписывание архитектуры в этот план не входят: имеющихся компонентов достаточно, чтобы проверить перечисленные гипотезы.
